# Desk 开发进度说明

最后更新：2026-08-25

## 当前定位

Desk 当前处于开发预览阶段，版本号为 `0.1.0`。本阶段目标是验证 TNotes 本地知识库在桌面端的浏览、可视化编辑、源码编辑和 Git 工作流，不作为稳定发行版使用。

当前不创建版本标签和 GitHub Release，也不承诺安装包兼容性。功能进入稳定阶段后，再统一处理正式版本号、代码签名、多平台安装包和发布流程。

## 已完成能力

### 工作区与知识库

- 打开一个父目录，扫描其直接子目录中的 `TNotes.*` 知识库。
- 校验 `.tnotes.json`、`TOC.md` 和 `notes`；异常知识库仍显示在列表中，并提供诊断入口。
- `TOC.md` 作为目录结构的唯一真相源；目录变更同步更新 `TOC.md` 和 `sidebar.json`，不改写根 `README.md`。
- 知识库图标复用于笔记标签，便于区分来自不同知识库的笔记。
- 显示 Git 变更数量、文件分组及 ahead/behind 状态，支持拉取、提交推送、空闲自动推送和冲突时跳转 IDE。

### 笔记与目录

- 笔记支持可视化编辑、只读和 Markdown 源码三种视图。
- 可视化和只读视图使用 Milkdown / Crepe，支持传统 Markdown、GFM、任务列表、表格、代码块和 KaTeX。
- TNotes 特殊组件、自定义容器及 HTML 等非标准源码以不可编辑的原子卡片保留，可切换源码视图编辑；Mermaid 和思维导图暂按代码块编辑。
- Core 生成的首个标题和 region TOC 作为不可编辑原子保护，避免用户输入在 Core 重新生成时无声丢失。
- Markdown 源码保护层确保未编辑文档字节级零 diff；编辑普通块时保留其它块的原始空白、列表标记、引用定义和代码围栏元数据。
- 目录支持文档与分组拖拽、自动展开父级、跨知识库标签定位和可配置的标签联动定位。
- 保存时复用 `@tnotesjs/core` 的标题、编号和 TOC 规则；可视化编辑会关闭整篇 Prettier，以保留未编辑源码。

### 标签与编辑区域

- 笔记标签和网页标签可以共存，每个标签相互独立。
- 支持临时标签、固定标签、右键菜单、标签数量上限、先进先出关闭和溢出换行配置。
- 支持拆分编辑区域，以及与 Chrome / VS Code 习惯一致的常用标签快捷键。
- 网页标签可以访问普通网页，也可以承载 `pnpm tn:dev` 启动的本地站点。

### 编辑体验与本地集成

- 源码视图使用 CodeMirror 6，并采用 GitHub Light / GitHub Dark 配色。
- 可视化编辑器按需加载；本地相对图片仅在呈现层映射到受保护的 `tnotes-asset` 协议，不改写 Markdown 地址。
- 编辑工具栏使用图标和非原生悬浮提示，展示操作语义与快捷键。
- 提供常用 Markdown 编辑快捷键及应用内快捷键清单。
- 图片默认写入笔记目录下的 `assets`；可选 GitHub 图床，上传失败时回退到本地。
- 支持通过右键菜单在 VS Code 或 Cursor 中打开知识库和笔记。
- 全文搜索使用后台 Worker 和持久化增量索引。
- 设置和会话保存在本机；GitHub Token 通过系统安全存储加密。

## 当前验证状态

提交前需要通过以下检查：

```bash
pnpm lint
pnpm test
pnpm typecheck
pnpm build
pnpm exec prettier --check .
```

当前自动化测试覆盖编辑区布局、标签状态与队列、主进程标签快捷键、TOC 节点行为、Milkdown 同步与只读行为、Markdown 源码保护、原子块投影、源码编辑器、图片路径安全和保存竞态等关键逻辑。两套 playground 知识库共 76 篇真实笔记已完成只读解析和局部编辑 round-trip 验证。macOS arm64 开发包已用于本地体验；Windows 和 Linux 目前仅由构建流程覆盖，尚未完成真实设备验收。

## 已知限制

- 可视化编辑器已覆盖常用传统 Markdown；TNotes 特殊组件和自定义容器当前只提供源码保真卡片，Mermaid 和思维导图暂按代码块呈现，均不提供专用可视化编辑或只读渲染。
- H2 和生成目录的折叠交互尚未迁移到 Milkdown；复杂粘贴、移动端布局和部分光标细节仍需持续打磨。
- 目录拖拽、多分区标签布局及部分边界状态仍需继续对齐语雀、VS Code、Typora 和 Obsidian 的体验。
- 当前不提供独立本地历史、内置 AI 助手和 diff 标签；历史回溯由 Git 负责。
- GitHub 图床的真实上传需要用户自行配置有效凭据。
- 安装包尚未进行代码签名、公证和完整的 Windows / Linux 兼容性验收。
- Desk 当前锁定 `@tnotesjs/core@0.6.0`；后续升级 Core 时需要同步验证 Workspace 与 Markdown API 的兼容性。

## 仓库提交约定

Desk 使用 NPM 上发布的 `@tnotesjs/core@0.6.0`，不再依赖同级 Core 仓库。涉及 Core API 的联动改动按以下顺序提交：

1. 完成 Core 检查、合并与 NPM 版本发布。
2. 在 Desk 中锁定新的 Core 版本并更新锁文件。
3. 独立完成 Desk 的安装、检查、测试与构建后再推送。

Desk 自身仍处于开发预览阶段；发布 Core 依赖不代表需要创建 Desk 的版本标签或 GitHub Release。

## 后续重点

- 继续完善 Milkdown 可视化编辑的粘贴、键盘、选区、无障碍和复杂文档兼容性。
- 为特殊组件、Mermaid、思维导图和自定义容器逐步增加独立的 NodeView 编辑与只读渲染。
- 补齐目录拖拽、多分区标签和键盘操作的交互细节。
- 在真实 Windows、macOS 和 Linux 环境完成兼容性验收。
- 稳定后再确定正式版本、签名方案及 GitHub Release 流程。
